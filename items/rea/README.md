# rea

## Tiếng Việt

### Dùng khi
- Muốn agent trả lời "feature này trong app hoạt động thế nào" bằng bằng chứng đo được (không đoán): mở app/binary/website đã có, trace tới code gây ra hành vi, trả về code + vị trí + độ chắc + phần chưa biết, rồi build lại feature tương tự cho project mình.
- Cần 1 MCP + CLI duy nhất phủ nhiều loại target: JavaScript/Electron, native binary (qua Hopper/Ghidra/IDA/Kuna), website (qua browser Chrome-family), .NET CIL, APK Android, firmware, model GGUF/safetensors, SQLite, WASM, EVM, IL2CPP/Rust/Go inventories — chạy local, kết quả kèm evidence.
- Muốn workflow kỷ luật cho reverse: decompile → hiểu (trace) → tái tạo, mọi kết luận map về observation/provenance/coverage, unknowns ghi rõ thay vì bịa.

### Bỏ qua khi
- Cần mod game PC sở hữu khép kín tới chạy thật + assets + clip + field note (recon → slice → verify → note) → dùng `../universal-modder/` (vòng 10 bước + `um` CLI + KB 242 notes) thay.
- Cần design tokens của site sống (colors/typography/drift gate) → dùng `../dembrandt/` thay (đo computed styles, không phân tích hành vi/code).
- Cần rebuild site sống 1:1 thành Next.js editable → dùng `../ai-website-cloner-template/` thay (Map → Observe → Build → Compare).
- Cần audit SEO (Health Score + plan + drift + GEO) → dùng `../claude-seo/` thay.
- Muốn phân tích target KHÔNG sở hữu/không được phép, ToS cấm reverse, vượt DRM/license, copy code/assets/brand người khác ra sản phẩm, dùng bản crack Hopper/IDA/JEB → cấm tuyệt đối (xem [Cốt lõi bất biến](#cot-loi-bat-bien)).

- Yêu cầu: Node.js `^22.23.4 || ^24.22.1 || >=26.12.1` + npm (nguồn `engines` trong `package.json` + `npm view rea-agents engines`, đo 01/11/2026). ### Phần tùy chỉnh
- Được đổi: target nào in-scope (đường dẫn tuyệt đối app/binary/APK/bundle/URL + phạm vi 1 feature, không cả suite), provider nào (`hopper/ghidra/ida/kuna`, `--provider` hoặc `provider_id`, `REA_ANALYSIS_PROVIDER`), profile schema MCP (`REA_MCP_INPUT_SCHEMA_PROFILE=compact/full`, `REA_MCP_OUTPUT_SCHEMA_PROFILE=compact/off`), engine settings (deadlines `REA_GHIDRA_*_TIMEOUT_MS`, `REA_HOPPER_*`, CDP/browser scope), output (`--json`, `--detail summary --evidence_output FILE`, `--format jsonl`, `--token-count`, `--timings`), snapshot reuse (`--snapshot PATH`, `open_binary snapshot_path`), clients đăng ký (`--client claude_code/codex/cursor/...`, `--skill=false`, `--dry-run`, `--yes` + scope). Cổng duyệt 2 tầng: (1) artifact nào — shortlist target + provider + scope 1 feature kèm lý do qua question tool, user pick mới chạy (native/binary loops + provider startup tốn thời gian/tiền license — log scope đã duyệt TRƯỚC khi chạy); (2) giữ/đổi gì — diff/evidence nào accept để rebuild, gap nào giữ lại. Waiver (bỏ evidence check, phân tích target nhạy cảm/không quyền, ship clone) phải quote câu ok tường minh của user, không suy diễn. Cấm đưa `must-not` (phân tích không quyền, crack engine, hứa tái tạo 100% chưa compare) vào danh sách tùy chỉnh.
- Sau khi dùng phải nêu được: evidence nào đã tái dùng (evidence_id + observation + unknowns) + provider/settings nào + rebuild verify gì; không nêu được = chưa thực sự dùng hệ.

### Phân công ai làm gì
- Agent chính: check quyền/ToS/license target + shortlist target/provider/scope 1 feature (chờ user pick — cấm tự chốt target rồi phân tích), chạy setup/CLI/MCP (`rea setup --dry-run`, `rea doctor`, `analyze`/`inspect-*`/`trace`/`compare`), trình evidence + confidence + unknowns + rebuild diff, xin duyệt rebuild/ship; verify file Evidence tồn tại + snapshot match + rebuild test xanh.
- Giao cho claude các bước cần browser/người thật: quan sát web đa state qua browser thật + chụp compare/screenshot, review visual rebuild vs gốc mắt người, reverse-check đụng trademark khi học — kèm URL + states + yêu cầu cụ thể; lệnh delegate `claude --chrome --model sonnet -p "<target + feature + states + output mong đợi>" --dangerously-skip-permissions --output-format text`; cấm agent tự bịa observation. Không có engine/browser tương ứng thì agent phải khai báo + dừng ở mức docs (cấm claim đã phân tích).
- Agent verify: Evidence bundle tồn tại + mở được (`evidence-import`/`inspect-analysis-view`) + unknowns liệt kê đủ + rebuild chạy + không mang code/assets/brand gốc sang sản phẩm.

### Usecase con 1: phân tích tĩnh JS/Electron không cần engine
- Khi dùng: có thư mục app JS/Electron đã giải nén hoặc `.asar` (sở hữu/được phép/học) cần application graph + Evidence để hiểu/trace/rebuild 1 feature.
- Khi bỏ qua: native binary → Usecase 2; website sống → Usecase 3; inventories khác (APK/.NET/firmware/model) → Usecase 4.
- Cơ chế khác các usecase khác ở đâu: duy nhất chạy static parser built-in (đọc files, không chạy app, không cần Hopper/Ghidra/browser); các usecase khác cần engine/browser ngoài.
- Lệnh copy-paste: `npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json` (nguồn `README.md` + `docs/cli.md`; thay path tuyệt đối của target). Lưu + project gọn: `rea analyze-javascript-application /absolute/path/to/app --json > app-evidence.json` rồi project view (`inspect-analysis-view` với `{"view":{"kind":"summary"}}`).
- Ngưỡng số cần đạt: Evidence file tồn tại + mở được; summary ~KB từ Evidence hàng trăm MB (vd Obsidian 334MB → ~10KB, nguồn `docs/cli.md`); modules/imports/routes/IPC/native boundaries liệt kê + unknowns ghi rõ; không claim hành vi runtime chưa capture.
- Ví dụ input-output (minh họa — target/scope do user pick trước, không phải mặc định): input "hiểu clipboard trong Notion desktop (sở hữu đã xác minh), scope 1 feature" → output application graph + trace renderer → preload → IPC → main + rich format + unknowns (server-side nếu có) + rebuild tương tự cho project mình (case thật trong showcase Notion, nguồn `README.md`).
- Pitfalls riêng: đưa path tương đối/`.asar` sai → lệnh từ chối path rỗng/NUL (dùng path tuyệt đối, nguồn `docs/cli.md`); đọc Evidence trăm MB trực tiếp trong context → tràn (luôn lưu file + project summary/page); nhầm static với runtime (static không chạy app — cần hành vi sống thì sang Usecase 3 + `javascript-runtime-observation.md`).
- Phân công usecase này: agent chính check quyền + chạy CLI + trình Evidence summary + trace + unknowns (shortlist target/scope qua question tool, user pick mới chạy); giao claude khi cần screenshots/compare trên browser; verify bằng Evidence file + view mở được + unknowns.

- Lệnh copy-paste: `rea providers --json` (liệt kê provider) rồi `rea analyze /absolute/path/to/program --provider ghidra --json` (nguồn `docs/cli.md`); sâu hơn: `rea search <bin> "text" --provider ghidra --json`, `rea function <bin> main --provider ghidra --json`, `rea decompile <bin> 0x1000 --provider ghidra --json`, `rea xrefs <bin> 0x1000 --provider ghidra --json`, `rea trace <bin> "text" --provider ghidra --json`. Snapshot: thêm `--snapshot /absolute/path/to/analysis/program.json` để reuse.
- Ngưỡng số cần đạt: provider bound đúng session (`provider_id` giữ tới khi switch/close); dossier đầy đủ pseudocode + references + unknowns; snapshot reuse chỉ khi bytes/operation/params/provider/settings khớp exact (mismatch báo `binding_mismatch`); dossier lớn dùng `--detail summary --evidence_output FILE` + page bundle, không đổ MB vào context.
- Ví dụ input-output (minh họa — target/provider do user pick trước): input "khôi phục công thức sound-pan trong game DOS cũ (sở hữu đã xác minh), provider ghidra" → output pseudocode + instructions + C tái tạo pass 3.205 case + 63 bytes khớp (case thật DX-Ball, nguồn `README.md` showcase) + gaps (phần compiler-specific chưa chắc).
- Pitfalls riêng: nhiều provider cùng hỗ trợ mà không `--provider` → lỗi `ambiguous` (chọn trong `candidate_ids`); provider chưa sẵn → `provider_unavailable` (chạy `rea doctor --provider ID --json` sửa theo remediation, không đoán); one-shot timeout mà provider vẫn chạy nền (client timeout ≠ analysis dừng — đọc `analysis_activity`); Hopper macOS `.hop` database không mở qua bridge (chọn executable gốc, nguồn `docs/installation.md`).
- Phân công usecase này: agent chính check quyền/license engine + chọn provider + chạy analyze/search/function/decompile + trình dossier + unknowns (shortlist provider/scope qua question tool); giao claude observe/compare visual khi cần; verify bằng Evidence + snapshot match + rebuild test.

### Usecase con 3: quan sát website + runtime hành vi
- Khi dùng: có URL/app sở hữu/được phép cần page structure/scripts/network observations/screenshots/scenarios + so sánh 2 bản + dựng RL environment từ API ghi lại.
- Khi bỏ qua: app local tĩnh → Usecase 1; binary → Usecase 2; chỉ cần inventories → Usecase 4.
- Cơ chế khác các usecase khác ở đâu: duy nhất chạy browser thật qua CDP/Playwright + captures (HAR — HTTP Archive /SAZ — Fiddler capture /pcap) + scenarios có khai báo + screenshots trong origin scope; target chạy bằng quyền user (có side-effects — đọc guide trước).
- Lệnh copy-paste: `rea capture-web-screenshot` / `rea capture-browser-scenario` / `rea analyze-web-bundle` (danh sách trong `npx -y rea-agents@6.8.0 --help` + `docs/cli.md` + `docs/browser-observation.md`); captures: `capture.py` (mitmdump) cho HAR/SAZ (nguồn `docs/web-network-captures.md`); so sánh: `rea compare-web-captures` / `compare-web-screenshots`.
- Ngưỡng số cần đạt: target trong origin scope đã duyệt; Evidence ghi structure/scripts/network + screenshots + unknowns (phần server-side không quan sát được); scenario bounded + replay được; RL environment export chạy + test cơ bản xanh (nguồn `README.md` mục Build RL environments).
- Ví dụ input-output (minh họa): input "hiểu scheduling rules trên booking page của mình (sở hữu đã xác minh)" → output rules suy từ page + scheduler rebuild trong vài prompts (case thật trong bài Substack 18/10/2026) + unknowns (server validation chưa thấy).
- Pitfalls riêng: site ToS cấm automated access thì dừng (FAIL pháp lý nếu cố); launches chạy bằng quyền user — tác động thật (đọc guide effects trước); browser mode headless vs visible khác state (ghi rõ mode khi compare); server-side logic không có trong files → Unknown, cấm suy ra fact.
- Phân công usecase này: agent chính check quyền/ToS + shortlist URL/scope/scenario (user pick) + chạy capture + trình observations + unknowns; giao claude thao tác browser đa state + chụp compare; verify bằng Evidence + screenshots + replay.

### Usecase con 4: inventory tĩnh offline managed/apk/firmware/model
- Khi dùng: cần metadata/inventory 1 loại artifact cụ thể mà không cần engine nặng (CIL .NET, APK, IL2CPP, Go/Rust, PE/ELF, Godot PCK, UnityFS, ESP/firmware, UF2, models, SQLite, WASM, EVM...).
- Khi bỏ qua: cần hiểu 1 feature end-to-end → Usecase 1/2/3 (usecase này chỉ inventories, không trace feature).
- Cơ chế khác các usecase khác ở đâu: mỗi artifact 1 lệnh `inspect-*` đọc bytes tĩnh (không chạy, không provider); một số cần caller-supplied tool (JADX + JDK, adb, Apktool, WABT, tshark, sigrok, pwntools); các usecase khác trace theo feature.
- Lệnh copy-paste: `rea inspect-managed-artifact /absolute/path/Assembly.dll --json` rồi `rea inspect-managed-members /absolute/path/Assembly.dll --type Example.Parser --json` (nguồn `docs/cli.md` mục Managed assemblies; thay type thật từ output); Go/Rust: `rea inspect-go-binary <bin> --json` / `rea inspect-rust-binary <bin> --json`; model: `rea inspect-model-artifact model.gguf --json` (`--hash full` để SHA-256 cả file); IL2CPP: `rea inspect-il2cpp-metadata global-metadata.dat --json` (chỉ v24/27/29/31/39).
- Ngưỡng số cần đạt: đúng lệnh cho đúng container (`.exe` PE/CLI mới parse CIL — single-file host/IL2CPP/NativeAOT không; APK cần JADX+JDK đầy đủ; format ngoài phạm vi báo Unknown + next probe, vd kernel module gzip/xz/zstd → `external_decompression`); absence quan sát được (thiếu security directory/import dir = observed absence, không phải không có).
- Ví dụ input-output (minh họa): input "lấy metadata assembly .NET của tool mình (sở hữu đã xác minh)" → output identity + members CIL theo type + native deps + unknowns (single-file/NativeAOT nếu gặp) — không chạy assembly.
- Pitfalls riêng: nhầm container (đưa single-file host cho managed parser → sai); SQLite cần Node 24.15+/26+ giới hạn native (nguồn README bảng target); PDA: `inspect_*` lớn cần `--detail summary --evidence_output FILE`, cấm đổ full vào context; caller-supplied tool thiếu (WABT/adb/tshark...) → lỗi config, chạy `rea doctor --json` + cài đúng tool.
- Phân công usecase này: agent chính xác định đúng container + chạy `inspect-*` đã duyệt + trình inventory + unknowns; giao claude khi cần đối chiếu visual/docs ngoài; verify bằng Evidence + format/version khớp.

## English

### When to use
- An agent must answer "how does this feature work" with measured evidence (never guesses): open an owned/permitted app, binary, or website, trace to the causing code, return code + locations + confidence + unknowns, then rebuild a similar feature for your own project.
- One MCP + CLI must cover many target kinds: JavaScript/Electron, native binaries (via Hopper/Ghidra/IDA/Kuna), websites (via Chrome-family browsers), .NET CIL, Android APKs, firmware, GGUF/safetensors models, SQLite, WASM, EVM, IL2CPP/Rust/Go inventories — local runs with evidence attached.
- A disciplined reverse flow is required: decompile → understand (trace) → recreate, every conclusion mapped to observations/provenance/coverage, unknowns recorded instead of invented.

### When to skip
- Closed-loop owned-PC-game modding (recon → slice → verify → note) → use `../universal-modder/` (10-step loop + `um` CLI + 242-note KB) instead.
- Live-site design tokens (colors/typography/drift gates) → use `../dembrandt/` instead (measured computed styles, no behavior/code analysis).
- 1:1 live-site rebuilds as editable Next.js → use `../ai-website-cloner-template/` instead (Map → Observe → Build → Compare).
- SEO audits (Health Score + plan + drift + GEO) → use `../claude-seo/` instead.
- Unowned/unpermitted targets, ToS-banned reversing, DRM/license bypass, shipping someone else's code/assets/brand, cracked Hopper/IDA/JEB copies → absolutely forbidden (see [Invariant core](#invariant-core)).

### Install

Linux additionally needs a procps-compatible `ps` on `PATH` for Ghidra/JADX/firmware/static-JS (source: `docs/installation.md`, "Linux owned-process prerequisite").
- Agent setup (source: `docs/installation.md`, cross-checked): `npx rea-agents setup` (pick agents, review the plan, approve; `npx rea-agents@latest setup` for the newest release). Skill-only without MCP: `npx skills add morluto/rea --skill reverse-engineer-anything`.
- No-install CLI: `npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json` (sources: `README.md` + `docs/cli.md`). Global install for the `rea` command: `npm install --global rea-agents`, then `rea --help`. Update: `rea update`.
- MCP auto-registration: `rea setup` registers the server + skill for selected clients (Claude Code, Codex, Cursor, Gemini CLI, OpenCode... — see [How the item works](#how-the-item-works)); check with `rea doctor --json`, single engine via `rea doctor --provider ghidra --json` (source: `docs/installation.md`).

### How the item works
- Backing organization: individual `morluto`, repo `https://github.com/morluto/rea`, MIT license, npm `rea-agents@6.8.0` (sources: `package.json` + `npm view`, measured 01/11/2026). GitHub API 01/11/2026: 417,980 stars / 104,440 forks / 1,589 open issues, pushed `2026-11-01T17:45:08Z`. npm `api.npmjs.org` 01/11/2026: 1,172,649 downloads in the trailing month (30/09–29/10/2026). Site `https://rea.tools` + guides/showcases. TypeScript + `playwright-core 1.64.1` + `@modelcontextprotocol/* 2.3.1` + optional `frida 17.23.2` (source: `package.json` dependencies).
- Core method: the agent calls REA via MCP (or a human calls the CLI directly); REA opens the target with the matching engine (real browser for web, Hopper/Ghidra/IDA/Kuna for native, built-in static parsers for JS/.NET/APK/firmware/models...), traces to the behavior-causing code, and returns findings with a 3-tier evidence model — Seen (fact + location), Inferred (pattern guess, must be tested), Unknown (absent from files, never fabricated) — plus confidence, limitations, and coverage. CLI and MCP share workflows and evidence contracts; each CLI call is a separate process, so later queries must persist Evidence first (`--evidence-bundle`, snapshots). It measures the target at hand rather than reading a spec, so guess-vs-reality gaps surface. Analysis runs locally; the calling AI still sees the findings (sources: `README.md` + `docs/cli.md` + `docs/mcp-contracts.md`).
- Per-usecase differences: engine-free static JS/Electron analysis (one command → application graph + Evidence, see [Sub-usecase 1](#sub-usecase-1-engine-free-static-jselectron-analysis)) vs provider-backed native analysis (sessions + pseudocode/assembly/xrefs/decompilation, see [Sub-usecase 2](#sub-usecase-2-provider-backed-native-analysis-with-evidence)) vs website/runtime observation (CDP browsers + captures + screenshots, see [Sub-usecase 3](#sub-usecase-3-website--runtime-behavior-observation)) vs bulk offline static inventories (managed/APK/firmware/models, see [Sub-usecase 4](#sub-usecase-4-offline-static-inventories-managedapkfirmwaremodels)).

### Invariant core
- Rights before targets: analyze only self-owned/permitted/internal-learning software (lawful research, education, interoperability, preservation); stop when the ToS bans reversing; honor vendor licenses. Violation = no longer using the system (legal FAIL). After every use, state the right basis (ownership/permission/learning) + ToS/license check. Sources: `DISCLAIMER.md` + `README.md` (Disclaimer/License).
- Evidence-backed, never invented: every conclusion maps to an observation (Seen) + provenance + confidence + coverage; Inferred is labeled as a guess + test plan; Unknown is explicit + next probes, never promoted to fact. No evidence_id/locations + unknowns = the system was not really used. Source: `docs/mcp-contracts.md` (Evidence) + `docs/cli.md` (Evidence import/export/compare).
- Separate tool licenses: commercial engines (Hopper/IDA/JEB) must be user-licensed per vendor terms; REA grants no key/activation and installs/updates no engine for you (except approval-gated Hopper setup). Cracked/stolen keys/bypasses = FAIL. Sources: `README.md` License section + `THIRD_PARTY_NOTICES.md`.
- Official sources only: take REA solely from `github.com/morluto/rea`, `rea.tools`, and npm `rea-agents` (the repo warns about lookalikes; source: `README.md` Important notice).

### Customizable surface
- Tunable: which in-scope target (absolute app/binary/APK/bundle path or URL + one-feature scope, never a whole suite), which provider (`hopper/ghidra/ida/kuna`, `--provider` or `provider_id`, `REA_ANALYSIS_PROVIDER`), MCP schema profiles (`REA_MCP_INPUT_SCHEMA_PROFILE=compact/full`, `REA_MCP_OUTPUT_SCHEMA_PROFILE=compact/off`), engine settings (deadline `REA_GHIDRA_*_TIMEOUT_MS` / `REA_HOPPER_*`, CDP/browser scope), output (`--json`, `--detail summary --evidence_output FILE`, `--format jsonl`, `--token-count`, `--timings`), snapshot reuse (`--snapshot PATH`, `open_binary snapshot_path`), registered clients (`--client claude_code/codex/cursor/...`, `--skill=false`, `--dry-run`, `--yes` + scope). Two-level approval gate: (1) which artifact — shortlist target + provider + one-feature scope with reasons via the question tool, run only after the user picks (native/binary loops + provider startup cost time/license money — log the approved scope BEFORE running); (2) what stays/changes — which diffs/evidence to accept for the rebuild, which gaps to keep. Waivers (skipping evidence checks, sensitive/unpermitted targets, shipping clones) must quote the user's explicit ok, never inferred. Never list `must-not` items (unpermitted analysis, cracked engines, unverified 100%-recreation promises) here.
- After use you must name: which evidence was reused (evidence_id + observations + unknowns) + which provider/settings + what the rebuild verified; otherwise the system was not really used.

### Work split
- Main agent: rights/ToS/engine-license checks + one-feature target/provider shortlist (wait for the user pick — never self-pick then analyze) + setup/CLI/MCP runs (`rea setup --dry-run`, `rea doctor`, `analyze`/`inspect-*`/`trace`/`compare`) + presenting evidence + confidence + unknowns + rebuild diffs + requesting rebuild/ship approval; verifies Evidence files exist + snapshots match + rebuild tests green.
- Hand browser/human-gated steps to claude: multi-state web observation in a real browser + comparison captures/screenshots, human visual review of rebuild vs origin, lookalike/trademark reverse-checks when studying — with URLs + concrete states; delegate via `claude --chrome --model sonnet -p "<target + feature + states + expected output>" --dangerously-skip-permissions --output-format text`; never invent observations. Without the matching engine/browser, declare it and stop at docs level, never claim analysis.
- Agent verifies: Evidence bundles exist and open (`evidence-import`/`inspect-analysis-view`) + unknowns fully listed + rebuild runs + no origin code/assets/brand shipped into the product.

### Differentiating positioning (numbers as of 01/11/2026 unless noted)

### Sub-usecase 1: engine-free static JS/Electron analysis
- When to use: an extracted JS/Electron app directory or `.asar` (owned/permitted/learning) needs an application graph + Evidence to understand/trace/rebuild one feature.
- When to skip: native binaries → Sub-usecase 2; live websites → Sub-usecase 3; other inventories (APK/.NET/firmware/models) → Sub-usecase 4.
- How its mechanism differs: the only flow using built-in static parsers (reads files, never runs the app, no Hopper/Ghidra/browser); all other sub-usecases need outside engines/browsers.
- Copy-paste command: `npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json` (sources: `README.md` + `docs/cli.md`; substitute the absolute target path). Persist + project small: `rea analyze-javascript-application /absolute/path/to/app --json > app-evidence.json`, then project views (`inspect-analysis-view` with `{"view":{"kind":"summary"}}`).
- Numeric bar: Evidence file exists and opens; a hundreds-of-MB Evidence yields a ~KB summary (e.g. 334 MB Obsidian → ~10 KB summary, source: `docs/cli.md`); modules/imports/routes/IPC/native boundaries listed + unknowns explicit; no claims about uncaptured runtime behavior.
- Input-output example (illustrative — target/scope user-picked first, never a default): "understand clipboard in my owned Notion desktop app, one-feature scope" → application graph + renderer → preload → IPC → main trace + rich formats + unknowns (server-side if any) + a similar rebuild for my project (real Notion showcase case, source: `README.md`).
- Own pitfalls: relative/wrong `.asar` paths → empty-path/NUL refusal (use absolute paths, source: `docs/cli.md`); reading hundred-MB Evidence directly in context → overflow (always persist + project summary/page); confusing static with runtime (static never runs the app — live behavior needs Sub-usecase 3 + `javascript-runtime-observation.md`).
- This sub-usecase's split: main agent rights-checks + runs the CLI + presents the Evidence summary + trace + unknowns (target/scope shortlist via question tool, user picks before running); hands browser screenshots/comparisons to claude when needed; verifies via Evidence files + openable views + unknowns.

### Sub-usecase 2: provider-backed native analysis with evidence
- When to use: an owned/permitted binary needs pseudocode/assembly/symbols/calls/xrefs/traces for one feature (including 16-bit DOS, GameCube DOL, experimental Windows P0).
- When to skip: static JS/Electron → Sub-usecase 1; live web → Sub-usecase 3; static-only inventories (Go/Rust/PE/ELF) → Sub-usecase 4.
- How its mechanism differs: the only flow opening a provider session (Hopper/Ghidra/IDA/Kuna) and keeping it + reusing snapshots; returns function dossiers (pseudocode + value flow + references) + deadline/recovery handling; other sub-usecases keep no provider session.
- Copy-paste commands: `rea providers --json` (list providers), then `rea analyze /absolute/path/to/program --provider ghidra --json` (source: `docs/cli.md`); deeper: `rea search <bin> "text" --provider ghidra --json`, `rea function <bin> main --provider ghidra --json`, `rea decompile <bin> 0x1000 --provider ghidra --json`, `rea xrefs <bin> 0x1000 --provider ghidra --json`, `rea trace <bin> "text" --provider ghidra --json`. Snapshots: append `--snapshot /absolute/path/to/analysis/program.json` for reuse.
- Numeric bar: the provider stays bound to the session (`provider_id` until switch/close); dossiers carry pseudocode + references + unknowns; snapshot reuse only on exact bytes/operation/params/provider/settings match (mismatches report `binding_mismatch`); oversized dossiers use `--detail summary --evidence_output FILE` + bundle paging, never MB-scale context dumps.
- Input-output example (illustrative — target/provider user-picked first): "recover the sound-pan formula in my owned legacy DOS game, ghidra provider" → pseudocode + instructions + C reimplementation passing 3,205 cases with 63 matching bytes (real DX-Ball case, source: `README.md` showcase) + gaps (compiler-specific parts uncertain).
- Own pitfalls: several providers support the target but no `--provider` given → `ambiguous` error (pick from `candidate_ids`); unready provider → `provider_unavailable` (run `rea doctor --provider ID --json` and follow the remediation, never guess); one-shot timeouts while the provider keeps running in the background (client timeout ≠ analysis stop — read `analysis_activity`); macOS Hopper `.hop` databases don't open via the bridge (select the original executable, source: `docs/installation.md`).
- This sub-usecase's split: main agent checks rights/engine licenses + picks the provider + runs analyze/search/function/decompile + presents dossiers + unknowns (provider/scope shortlist via question tool); hands visual observation/comparison to claude when needed; verifies via Evidence + snapshot matches + rebuild tests.

### Sub-usecase 3: website + runtime behavior observation
- When to use: an owned/permitted URL/app needs page structure/scripts/network observations/screenshots/scenarios + two-build comparisons + RL environments built from recorded APIs.
- When to skip: local static apps → Sub-usecase 1; binaries → Sub-usecase 2; inventories only → Sub-usecase 4.
- How its mechanism differs: the only flow driving a real browser via CDP/Playwright + captures (HAR/SAZ/pcap) + declared scenarios + in-origin-scope screenshots; launched targets run with user permissions (real side effects — read the guide first).
- Copy-paste commands: `rea capture-web-screenshot` / `rea capture-browser-scenario` / `rea analyze-web-bundle` (listed in `npx -y rea-agents@6.8.0 --help` + `docs/cli.md` + `docs/browser-observation.md`); captures via `capture.py` (mitmdump) for HAR/SAZ (source: `docs/web-network-captures.md`); comparisons via `rea compare-web-captures` / `compare-web-screenshots`.
- Numeric bar: targets stay inside the approved origin scope; Evidence records structure/scripts/network + screenshots + unknowns (unobservable server-side parts); scenarios are bounded and replayable; exported RL environments run + pass a basic smoke test (source: `README.md`, Build RL environments).
- Input-output example (illustrative): "understand the scheduling rules on my own booking page (ownership verified)" → page-derived rules + a rebuilt scheduler in a few prompts (real case via the 18/10/2026 Substack review) + unknowns (unseen server validation).
- Own pitfalls: ToS-banned automated access → stop (pushing through = legal FAIL); launches run with user permissions — real effects (read the effects guide first); headless vs visible browser modes differ by state (record the mode on every comparison); server-side logic absent from files → Unknown, never promoted to fact.
- This sub-usecase's split: main agent checks rights/ToS + shortlists URLs/scope/scenarios (user picks) + runs captures + presents observations + unknowns; hands multi-state browser operation + captures to claude; verifies via Evidence + screenshots + replay.

### Sub-usecase 4: offline static inventories (managed/APK/firmware/models)
- When to use: metadata/inventory of one specific artifact kind is needed with no heavy engine (CIL .NET, APKs, IL2CPP, Go/Rust, PE/ELF, Godot PCK, UnityFS, ESP/firmware, UF2, models, SQLite, WASM, EVM...).
- When to skip: end-to-end one-feature understanding → Sub-usecases 1/2/3 (this one yields inventories only, no feature traces).
- How its mechanism differs: one `inspect-*` command per artifact reading static bytes (never executes, no provider); some need caller-supplied tools (JADX + JDK, adb, Apktool, WABT, tshark, sigrok, pwntools); other sub-usecases trace by feature.
- Copy-paste commands: `rea inspect-managed-artifact /absolute/path/Assembly.dll --json`, then `rea inspect-managed-members /absolute/path/Assembly.dll --type Example.Parser --json` (source: `docs/cli.md`, Managed assemblies section; substitute a real type from the output); Go/Rust: `rea inspect-go-binary <bin> --json` / `rea inspect-rust-binary <bin> --json`; models: `rea inspect-model-artifact model.gguf --json` (`--hash full` for whole-file SHA-256); IL2CPP: `rea inspect-il2cpp-metadata global-metadata.dat --json` (versions 24/27/29/31/39 only).
- Numeric bar: the right command for the right container (PE/CLI `.exe` for the managed parser — not single-file hosts/IL2CPP/NativeAOT; APKs need a complete JADX+JDK; out-of-range formats report Unknown + next probe, e.g. gz/xz/zstd kernel modules → `external_decompression`); observed absence (missing security/import directories = absence of that table, not of everything).
- Input-output example (illustrative): "inventory the .NET assembly of my own tool (ownership verified)" → identity + per-type CIL members + native dependencies + unknowns (single-file/NativeAOT when hit) — the assembly is never executed.
- Own pitfalls: wrong container (single-file host fed to the managed parser → wrong); SQLite needs Node 24.15+/26+ native limits (source: README target table); large `inspect_*` outputs need `--detail summary --evidence_output FILE`, never full context dumps; missing caller-supplied tools (WABT/adb/tshark...) → configuration errors, run `rea doctor --json` and install the exact tool.
- This sub-usecase's split: main agent identifies the exact container + runs the approved `inspect-*` + presents inventory + unknowns; hands visual/docs cross-checks to claude when needed; verifies via Evidence + matching format/version.

### Shared steps
1. Verify target rights + ToS/engine licenses (owned/permitted/learning) → shortlist target + provider + one-feature scope via the question tool, user picks before running (log the scope FIRST — provider time/licenses cost).
2. One-time setup: `npx rea-agents setup` (review the plan + approve + restart the agent) → `rea doctor --json` (scoped `--provider`/`--client` when needed).
3. Analyze per sub-usecase (UC1 static-JS / UC2 native-provider / UC3 web-runtime / UC4 inventories) — persist Evidence to files, project summary/pages instead of reading full dumps.
4. Trace the feature → Seen/Inferred/Unknown + confidence + coverage; every Inference ships a test plan.
5. Rebuild one feature for your own project (no origin code/assets/brand carried over) → test + compare against the origin.
6. Deliver: commands run + Evidence/snapshot paths + unknowns + checked rights (owned/permitted/learning) + engine licenses.

### Pitfalls
- Analyzing unpermitted/ToS-banned targets, DRM/license bypasses, or cracked Hopper/IDA/JEB copies → legal FAIL (sources: `DISCLAIMER.md` + License); the only offer is to stop + suggest lawful routes.
- Installing REA from unofficial sources (strange npm tags/forks/copied READMEs) → malware risk; fix: only `github.com/morluto/rea` + `rea.tools` + npm `rea-agents` (source: README Important notice).
- Wrong Node patch (`v24.22.0` here < required `24.22.1`) → `EBADENGINE` (hit 01/11/2026); fix: upgrade Node to the exact patch first — the installer never upgrades Node for you.
- Missing procps-compatible `ps` on Linux → providers/static-JS refuse before spawning (`capability_unavailable`/`provider_unavailable`); fix: install `procps`/`procps-ng` on `PATH` (source: installation doc).
- Dumping hundred-MB Evidence into context → overflow; fix: always `--detail summary --evidence_output FILE` + `inspect-analysis-view` paging (e.g. a 334 MB app → ~10 KB summary).
- Trusting mismatched snapshots (`binding_mismatch`: differing bytes/provider/params/profile) → wrong conclusions; fix: compare digests + re-analyze when they differ.
- Reading Inferred as Seen (building on a pattern guess directly) → "runs, but not as intended"; fix: label + test before relying (Seen/Inferred/Unknown rule).
- Shipping a whole-suite clone with origin code/brand → IP exposure; fix: rebuild one feature + distinct brand/assets/servers, check terms before selling.
